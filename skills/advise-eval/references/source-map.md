# Verified source map

The recommendations in `SKILL.md` were checked against the following primary documentation and original research. URLs are kept here so an agent can re-check time-sensitive details.

- [OpenAI Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices): task-specific evals, production-shaped data, logging, human calibration, continuous evaluation, and comparison/classification/scoring tasks.
- [Anthropic: Define success criteria and build evaluations](https://platform.claude.com/docs/en/test-and-evaluate/develop-tests): measurable multidimensional criteria and choosing code, human, or LLM grading by reliability and nuance.
- [LangSmith evaluation concepts](https://docs.langchain.com/langsmith/evaluation-concepts): component-level evaluation, offline datasets, online traces, experiments, and reference-based versus reference-free evaluation.
- [Ragas available metrics](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/): RAG and agent metric names including context precision/recall, faithfulness, tool-call accuracy, and goal accuracy. Treat metric definitions as library-specific implementations, not universal ground truth.
- [Judging LLM-as-a-Judge](https://arxiv.org/abs/2306.05685): evidence that capable judges can correlate with human preferences while exhibiting biases including position, verbosity, and self-enhancement effects.
- [A Survey on LLM-as-a-Judge](https://arxiv.org/abs/2411.15594): taxonomy and reliability/bias research. Use it as a survey, not as a guarantee that any judge is valid for a specific domain.
- [JudgeBench](https://arxiv.org/abs/2410.12784): evaluates judges on difficult knowledge, reasoning, math, and coding comparisons; supports testing the judge itself rather than assuming it is reliable.
- [Systematic study of position bias](https://arxiv.org/abs/2406.07791): motivation for order randomization and order-swapped checks in pairwise evaluation.

The multi-agent judge patterns, bias-detection protocol, and production-readiness/drift-monitoring criteria in `references/multi-agent-judges.md` are syntheses of the judge-reliability sources above (especially the LLM-as-a-Judge survey and JudgeBench) combined with standard measurement-system practice — versioning, calibration against human labels, monitoring, and rollback. They are engineering recommendations, not claims backed by a single citable benchmark. The frozen anchor-set method for separating system drift from judge drift is a design pattern, not a published result; validate it on your own data before relying on it. Two items in that document are not covered by any of the sources above and should be treated as unverified engineering hypotheses: the "recency / context position" bias row (a long-context effect distinct from the pairwise position bias the cited position-bias study measures) and the debate/critique judging pattern (not evaluated by any cited source here). Validate both on your own calibration data before relying on them.

`SKILL.md` no longer gives fixed dataset sizes: none of the sources above establishes one. It points instead to the following, all re-checked on October 13, 2026:

- [Adding Error Bars to Evals](https://arxiv.org/abs/2411.00640): treats evaluations as experiments and gives formulas for standard errors, paired differences between two models, and planning an evaluation. A method paper, not a benchmark.
- [NIST/SEMATECH e-Handbook, confidence intervals for proportions](https://itl.nist.gov/div898/handbook/prc/section2/prc241.htm): documents the exact binomial interval. The zero-failure upper bound `1 − 0.05^(1/n)` quoted in `SKILL.md` (about 5.8% at n = 50, about 0.997% at n = 299) is derived by setting the observed failure count to zero in that definition and was checked numerically; NIST does not discuss the zero-failure case itself. It assumes independent, representative sampling.
- [Preserving Statistical Validity in Adaptive Data Analysis](https://arxiv.org/abs/1411.2664): standard inference assumes hypotheses are fixed before the data are seen; repeated selection on one dataset breaks that assumption, which is why the release set must stay separate from anything you tune on.
- [Anthropic: Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) (January 9, 2026): read transcripts; a 0% pass rate with frontier models is most often a broken task; a model's CORE-Bench score rose from 42% to 95% after grading, specification, and reproducibility bugs were fixed. First-party engineering guidance with examples.
- [Anthropic: Quantifying infrastructure noise in agentic coding evals](https://www.anthropic.com/engineering/infrastructure-noise) (February 5, 2026): container resource limits shifted Terminal-Bench 2.0 scores by 6 percentage points (p < 0.01). One benchmark family; effect sizes do not transfer unchanged.

The gate values in the example YAML in `SKILL.md` are illustrative placeholders, not sourced recommendations; set each from the decision's acceptable error rate and the uncertainty in the estimate.
